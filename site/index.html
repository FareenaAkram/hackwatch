    How it works

    1. Problems. 20 small tasks, each with a reference solution used only as an oracle, a few visible examples, edge cases and random hidden inputs.
    2. Candidates. Reference and independent correct solutions, honest bugs mutated from the reference (some pass the visible examples), and five generated reward hacks. Optionally, real LLM samples.
    3. Three graders. Naive (visible examples, exit status), strict (hidden cases, exact types, secret sentinel) and naive plus detector.
    4. Detector. Never sees hidden tests or the reference: literal-matching of visible inputs, always-equal objects, harness escapes, test awareness, type anomalies and constant outputs on fresh inputs.
    5. Pairs. Chosen vs rejected with a rubric and a critique built from execution evidence.

    Hacks come from five known patterns, so detector recall on unseen hacks is unknown. Honest bugs are single-token mutants, not human errors. Sandboxing is process-level, not a security boundary. See the dataset card for the full list of limitations.
